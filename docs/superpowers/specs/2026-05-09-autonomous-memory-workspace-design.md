# Autonomous Memory Workspace Design

> 日期: 2026-05-09
> 范围: 前后端主体验改造，弱化废弃 Workflow/Pipeline 叙事

## 背景

当前项目已经从固定 Workflow 迁移到 Agent Run，但前端仍像一组普通工具面板：聊天、运行、记忆、管线、监控并列展示。用户和评审难以直观看到本项目区别于常规工具的核心价值。

用户明确希望保留并放大两个亮点：

- 长期记忆系统：Agent 能召回、解释并沉淀长期上下文。
- 持续工作直到目标完成：系统围绕目标推进，而不是只执行一次固定流程。

Workflow 已经被放弃；Pipeline 只作为兼容能力保留，不再作为主叙事。

## 目标

把项目主入口改造成“目标驱动的长期记忆 Agent 工作台”：

1. 用户创建一个目标，而不是选择旧 Workflow。
2. 后端 Agent Run 显式支持 continuous 模式、完成标准、最大迭代、暂停、继续、停止。
3. 前端突出目标、记忆召回、当前步骤、工具调用、事件流和产物。
4. Pipeline 仅作为兼容入口弱化展示。

## 后端设计

### Run 状态

在现有 `TaskState` 上扩展字段：

- `mode`: 默认 `continuous`，表示持续工作语义。
- `strategy`: 默认 `memory_guided_agent_loop`。
- `max_iterations`: 单个目标最多推进轮数，默认 50。
- `iteration`: 当前已完成轮数。
- `completion_criteria`: 用户给出的完成标准。
- `auto_memory`: 是否把运行摘要写入记忆，默认开启。
- `status`: 增加 `paused`。

### 控制 API

`POST /api/runs/{run_id}/control` 支持：

- `pause`
- `resume`
- `cancel`

暂停/继续是协作式控制：如果 Agent 正在一次 LLM 或工具调用中，暂停会在下一轮循环前生效。

### 记忆上下文 API

新增：

- `GET /api/runs/{run_id}/memory-context`

返回本目标召回的相关记忆，包含检索分数、类型、内容和元数据，用于前端解释“记忆如何影响当前目标”。

### 持续运行语义

第一版不做不可控死循环。持续模式的工程边界是：

- 默认高上限迭代。
- 每轮写 transcript。
- 每轮注入目标、完成标准、当前轮数、记忆上下文和历史摘要。
- Agent 返回完成信号或达到终态时结束。
- 用户可暂停/继续/终止。

## 前端设计

### 主入口

`TaskPanel` 改为“目标工作台”：

- 标题从 Agent Run 工作区改为“目标工作台”。
- 顶部说明强调长期记忆和持续推进。
- 创建表单增加“完成标准”“最大迭代”“自动写入记忆”。
- 默认按钮文案为“启动持续工作”。

### 运行卡片

每个 Run 卡片展示：

- 目标标题。
- 当前状态和当前迭代。
- 完成标准。
- 记忆模式。
- 暂停/继续/终止按钮。
- 事件流。
- 记忆上下文侧栏。

### 导航叙事

侧边栏：

- “运行”改为“目标工作台”。
- Pipeline 改为“兼容管线”，移动到 System/Legacy 区域。
- 品牌文案从普通 Multi-Agent 改为 Memory Agent Workspace。

## 非目标

- 不恢复旧 Workflow。
- 不把 Pipeline 重新包装成主能力。
- 不暴露冗长内部推理链路。
- 不实现真正无限制的无终止循环。
- 不引入第三方 UI 库。

## 验收

- 后端测试覆盖 Run 控制状态、schema、记忆上下文 API。
- 前端构建通过。
- UI 首屏能明确表达“目标驱动 + 记忆 + 持续工作”。
